# 项目方案：Idea → 结构化研究者网络（工作名：**"学术社会地图"**）

## 一、项目一句话

> 输入一段 idea 文本，系统自动构建一张"这个 idea 所处学术社区的地图"——**谁在研究这个方向、谁引用谁（学派）、谁用谁的方法（方法谱系）、你该引谁、该联系谁**。

## 二、核心概念：什么是你要的"结构化研究者网络"

它不是单纯的关系图，而是**三层网络 + 一个锚点**：

```
         ┌─ ① 引用网络：论文→论文（谁影响谁）
三层网络 ─┼─ ② 研究者网络：作者→作者（合作/互引/同机构）
         └─ ③ 方法网络：论文→方法（谁提出/谁使用/谁改进）
         └─ 锚点：你的 idea（嵌入到三层网络的交叉位置）
```

**"社会事实先验"的含义**：①②③ 中的每一条边（"A 引用了 B""C 和 D 合作过""E 用了 F 的方法"）都是从 OpenAlex/Semantic Scholar **真实数据里取出来的客观事实**，不是 LLM 编的。LLM 只负责一件事——**从你的 idea 里猜"这个网络长什么样"，然后用真实数据去验证和填充**。先验负责"不胡说"，LLM 负责"找对入口"。

## 三、数据模型（项目的地基）

**节点（6 类）：**

| 节点 | 来源 | 说明 |
|---|---|---|
| Paper | OpenAlex/S2 | 种子论文 |
| Author | OpenAlex | 研究者 |
| Institution | OpenAlex | 机构 |
| Method | LLM 抽取+人工确认 | 方法实体（**唯一需要半人工的节点**） |
| Concept/Topic | OpenAlex concepts | 领域概念（自带层级） |
| Idea（你的锚点） | 输入 | 只有 1 个，网络的根 |

**边（8 类，全部来自真实数据）：**

```
Paper —cites→ Paper          （引用）
Paper —authored_by→ Author   （作者）
Author —collaborates→ Author （合著，2篇以上共同作者）
Author —affiliated→ Institution
Paper —uses→ Method          （方法使用，LLM抽取，需校验）
Method —extends→ Method      （方法改进谱系）
Paper —about→ Concept        （领域归属）
Author —author_cited_by→ Author （A的工作被B引用过 = "B 站在 A 肩膀上"）
```

## 四、系统架构（六层）

```
┌─ 输入层    idea 文本（一句话/一段话）
├─ 理解层    LLM 抽取：候选方法名 + 候选概念 + 生成3组检索query
├─ 锚定层    OpenAlex/S2 检索 Top-20 种子论文 → 实体链接（去重/消歧）
├─ 图构建层  种子论文 → 拉取引用链/作者/机构/概念 → 2~3跳扩展
├─ 推理层    社区检测（识别学派）+ 关键人物排序 + 方法谱系梳理
└─ 交付层    图谱可视化 + 结构化报告（该引谁/该联系谁/谁可能否证你）
```

## 五、核心流程（输入 → 输出的完整链路）

```
[你的 idea]
   │
   ▼
① LLM 理解：抽方法实体 + 概念 + 检索query
   │
   ▼
② 检索 Top-20 种子论文（OpenAlex：relevance 排序，免费无key限制宽松）
   │
   ▼
③ 锚定：把论文接入图 → 作者 → 机构 → 概念
   │
   ▼
④ 扩展：从种子论文做 2 跳引用追溯 + 合著者扩展 + 方法使用扩展
   │
   ▼
⑤ 推理：
   - 社区检测 → "这个方向有哪几个学派"
   - 作者排序 → "谁是核心人物（被引最多/连接最多）"
   - 方法谱系 → "你的方法可能站在谁的肩上"
   - 覆盖检查 → "哪些方向你可能没搜到"（继承 Stage 1.5 查漏逻辑）
   │
   ▼
⑥ 输出：
   - 交互式图谱（Neo4j 存储 + 可视化）
   - 报告：Top 核心作者 / 学派分布 / 方法谱系 / 潜在遗漏方向 / 建议联系的合作者
```

## 六、技术选型（全部免费/开源）

| 层 | 选型 | 理由 |
|---|---|---|
| 数据源 | **OpenAlex**（主）+ Semantic Scholar（辅） | 全开放 SKG，含作者/机构/概念；S2 补引用细节 |
| 存储 | **Neo4j**（Community 版） | 图查询 + 向量索引（承接前面聊的"图+向量"方案） |
| 抽取 | LLM（GPT/Claude/本地均可）+ 结构化输出 | 只做"猜测"，不产生事实边 |
| 向量 | BGE/E5 embedding | idea 与论文语义匹配 |
| 可视化 | Neo4j Bloom / Gephi / D3 | 交互式网络浏览 |
| 编排 | Python + LangGraph | 每步可审计、可断点续跑 |

## 七、MVP（最小可用版，2-3 周）

**范围收窄，先跑通核心价值：**
- 输入 idea → 输出：**Top-10 种子论文 + 作者引用网络（谁引用谁）+ 方法谱系图 + 核心人物 Top-5**
- 不做：机构网络、概念层级、社区检测（放 V2）
- 验证方式：拿 3 个你熟悉的领域跑，人工核对"网络里的人物/方法是否和你认知一致"

## 八、风险与边界（如实说）

1. **方法关系是唯一不"社会事实"的部分**——论文→方法 的边需要 LLM 从摘要抽取，**会错**。设计对策：方法节点先给"候选+置信度"，人工确认后才进图谱；
2. **实体消歧是经典难题**——同名作者（如"J. Wang"有几百个）。OpenAlex 有 author ID 可以缓解，但跨库合并仍需小心；
3. **2 跳以上扩展噪声陡增**——必须用"与 idea 的语义相关度"做剪枝，否则网络会蔓延成整个学科；
4. **覆盖盲区仍在**——OpenAlex 对非英语/灰色文献覆盖有限，"社会事实"也只能是"可获取数据中的社会事实"；
5. **免费额度的现实**——OpenAlex 无 key 限速约 10 万次/天（对个人项目够用）；S2 需要 key 且限速更紧。**数据源应以 OpenAlex 为主**。

## 九、为什么这个项目值得做（回到我们的讨论主线）

它把前面所有讨论串起来了：
- **查漏问题** → 从"找相似论文"升级为"看完整地图哪里有空位"；
- **新颖性判断** → 从"审稿人共识"升级为"网络定位"：你的 idea 落在图里哪个位置、周围是谁、**谁最可能否证你**——送审前自己先看一遍；
- **"社会事实先验"** → 是这张图可信的根基：**边是数据，不是幻觉**。
